# JsonDB website overhaul: design

Date: 2026-11-16. Agreed with Farooq in the brainstorming session that followed `WEBSITE_SESSION_BRIEF.md`.

## Goals

1. Replace the Jekyll site at https://jsondb.github.io with a modern, genuinely useful documentation site for `jsondb-core` 1.1.16.
2. Give JsonDB a proper icon.
3. Finish backlog issue #80 (repository hygiene) across `jsondb-core` and `jsondb.github.io`.

## Decisions

| Topic | Decision |
|---|---|
| Generator | Astro + Starlight, deployed by GitHub Actions |
| Palette | "Electric Indigo": indigo accent on zinc greys, with a cyan secondary |
| Icon | Concept C, refined: JSON braces around a database cylinder, on an indigo gradient tile |
| Landing page | Starlight splash page: hero, install snippet, six feature cards, a code ↔ `users.json` demo |
| Docs scope | Only what is published: release 1.1.16. Nothing from the CHANGELOG's *Unreleased* section |
| Analytics | None. Remove the dead Universal Analytics tag (`UA-86156909-1`) |
| Domain | https://jsondb.github.io, with no custom domain and no CNAME |

## Palette

Starlight's theme variables are overridden in `src/styles/theme.css`.

| Role | Light | Dark |
|---|---|---|
| Accent (links, buttons, active nav) | `#4f46e5` (indigo-600) | `#a5b4fc` (indigo-300) |
| Accent, high-contrast text on accent backgrounds | `#3730a3` | `#c7d2fe` |
| Accent, low (backgrounds, badges) | `#e0e7ff` | `#312e81` |
| Secondary highlight | `#0e7490` | `#67e8f9` |
| Background | `#ffffff` / `#fafafa` | `#09090b` / `#111114` |
| Greys | zinc scale (`#18181b` … `#e4e4e7`) | zinc scale (`#f4f4f5` … `#27272a`) |

Code blocks use Expressive Code with a light and a dark theme whose keywords pick up the accent. Text and accent pairs must meet WCAG AA contrast (4.5:1 for body text).

## Icon

All artwork uses a 64 × 64 grid on a rounded tile (`rx = 14`). The tile has a diagonal gradient `#818cf8 → #6366f1 → #4338ca` and a soft white highlight at the top.

- **Large artwork (48 px and up):**
  - white braces with a 4.6 stroke, points at x = 11 and 53;
  - a white cylinder of width 21 (x 21.5–42.5) with a `#a5b4fc` top ellipse;
  - two `#6366f1` bands.
- **Small artwork (32 px and below):**
  - braces with a 6.5 stroke;
  - a wider cylinder (x 20–44);
  - one thick band.

  This version is used for favicons and the header logo, which renders at about 28 px.
- **Monochrome mark:** braces and cylinder in `currentColor`, with the bands knocked out. Used for the README and as a single-colour fallback.

Files:

- Sources in `src/assets/`: `logo.svg` (large), `logo-small.svg` (small), `logo-mono.svg`.
- In `public/`:
  - `favicon.svg`, from the small artwork;
  - `favicon.ico`, with 16 and 32 px images from the small artwork and 48 px from the large;
  - `apple-touch-icon.png`, 180 px from the large artwork;
  - `og.png`, a 1200 × 630 social card with the large logo, the "JsonDB" wordmark and the tagline.
- The PNG and ICO files are generated by `scripts/build-icons.mjs` (using `sharp`). Both the script and its output are committed, so the site build never runs it.

## Docs structure (sidebar)

**Start here**
- Introduction: why JsonDB, and when not to use it
- Installation: Gradle, Maven, and the jar. One artifact `io.jsondb:jsondb-core:1.1.16`, Java 8+
- Quick start: a complete working program

**Guides**
- Defining documents: `@Document`, `@Id`, `@Secret`
- The JsonDBTemplate *(new)*:
  - constructors;
  - passing entity classes directly;
  - one instance per database folder, shared between threads;
  - the warning when a second instance opens the same folder;
  - `AutoCloseable` and try-with-resources.
- Android & OSGi *(new)*: pass entity classes directly, API 26+
- Inserting, saving & removing: `insert`, `save`, `upsert`, `remove`, single and batch
- Querying with XPath: JXPath syntax with examples, and `count()` *(new)*. Extension functions are disabled; core XPath functions still work.
- Sorting & slicing
- Updating with findAndModify:
  - `findAndModify` / `findAllAndModify`;
  - the `Update` conversion rules;
  - changing `@Id` is rejected.
- Encryption:
  - `Default1Cipher` (AES-GCM);
  - the deprecated `DefaultAESCBCCipher`;
  - `CryptoUtil.generate128BitKey`;
  - `changeEncryption()`.
- Schema versions: `updateCollectionSchema()`.
  - rename, add, delete;
  - add fills only missing or null values;
  - updates that would lose data are rejected.
- Backup & restore: zip files, replace and merge modes
- Watching for file changes: file-change listeners

**Reference**
- XPath query cheat sheet
- Upgrading from 1.0.x: the `-j8`/`-j11` artifacts are replaced by one artifact; the API changes
- Security notes: extension functions are disabled; dependency hygiene
- Javadoc ↗ (javadoc.io), Changelog ↗, Releases ↗

Pages that cover 1.1.x additions carry a "New" badge in the sidebar. Every page has "Edit this page on GitHub". Search is Starlight's built-in Pagefind.

Sources of truth for the content: `jsondb-core/CHANGELOG.md` (the 1.1.16 and 1.1.0 sections only), `jsondb-core/Readme.md`, the 1.1.16 source, and the existing usage page.

## CI and deployment

`.github/workflows/deploy.yml`:

- `on: pull_request` and `on: push` to `master`, plus `workflow_dispatch`.
- **Job `build`** (the required status check):
  - checkout;
  - setup-node using `.nvmrc`, with an npm cache;
  - `npm ci`, `npm run build`;
  - `actions/upload-pages-artifact` from `dist/`.
- **Job `deploy`:** runs only on a push to `master`. It needs `build`, uses the `github-pages` environment, and runs `actions/deploy-pages`. Permissions are `pages: write` and `id-token: write`.
- Concurrency group `pages`, which doesn't cancel a deploy already in progress.

**Cut-over:** the Pages source must change from "Deploy from a branch" to "GitHub Actions". This is a repository setting, changed only with Farooq's confirmation, when the site PR is merged. The previous deployment keeps serving until the first Actions deploy succeeds.

## Repository hygiene (#80)

- **`jsondb-core`:** one PR, adding only:
  - `.github/dependabot.yml`: Gradle, weekly;
  - `.github/ISSUE_TEMPLATE/bug_report.yml`: a YAML issue form with required JsonDB version, Java version and reproduction steps; optional Android API level / OSGi container, expected vs actual, and logs;
  - `.github/ISSUE_TEMPLATE/feature_request.yml`: problem, proposed solution, alternatives.

  This session touches no other `jsondb-core` file.
- **`jsondb.github.io`:** `.github/dependabot.yml` covering npm (all updates grouped into one weekly PR) and github-actions (weekly). It ships in the site PR. Dependabot security alerts are turned on for both repos if they aren't already; that's a settings change, so Farooq confirms first.
- **Branch protection for `jsondb.github.io` `master`,** applied after the site PR merges and only with Farooq's confirmation:
  - PR required, with 1 approving review;
  - bypass allowed only for FarooqKhan;
  - required status check `build`;
  - admins included.

  This matches `jsondb-core`.
- **Close #80** once all of the above is done.

## Out of scope

- Analytics.
- Versioned docs (one set for the latest release only).
